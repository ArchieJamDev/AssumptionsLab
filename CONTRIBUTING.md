# Contributing to AssumptionsLab

First of all, thank you for your interest in contributing to AssumptionsLab.

AssumptionsLab is more than a statistical software project. It is an educational and scientific initiative whose primary objective is to improve statistical practice through evidence-based methodological guidance.

We welcome contributions that improve the quality, reliability, usability, documentation, and educational value of the project.

---

# Guiding Principles

Every contribution should respect the following principles.

- Scientific accuracy comes before implementation speed.
- Recommendations must be supported by published methodological literature.
- Educational value is as important as computational correctness.
- New features should remain consistent with the overall architecture of the project.
- The user experience should remain clear, simple, and intuitive.

---

# Ways to Contribute

Contributions may include:

- Bug reports
- Feature requests
- Statistical validation
- Methodological improvements
- Documentation
- Code improvements
- Graphical interface enhancements
- Internationalization
- Performance optimization

---

# Before You Start

Before implementing a new feature, please:

1. Search existing Issues.
2. Read the project documentation.
3. Verify that your proposal is consistent with the project's methodological philosophy.
4. Open an Issue if the proposed change is substantial.

---

# Coding Standards

Please follow these general guidelines.

- Write clean and readable code.
- Prefer clarity over cleverness.
- Document functions whenever appropriate.
- Use meaningful variable names.
- Avoid unnecessary dependencies.
- Preserve compatibility with Jamovi whenever possible.

---

# Documentation

Documentation is considered part of the software.

Whenever appropriate, contributions should also update:

- User documentation
- Technical documentation
- Methodological Library
- Examples
- Comments within the source code

---

# Methodological Contributions

Methodological recommendations should:

- Be evidence-based.
- Reference recognized methodological literature.
- Avoid unsupported opinions.
- Be applicable to a broad research audience.
- Maintain consistency with existing recommendations.

---

# Pull Requests

Before submitting a Pull Request, please ensure that:

- The code compiles correctly.
- Existing functionality is not affected.
- Documentation has been updated when necessary.
- New features follow the existing interface conventions.
- Changes are clearly described.

Small Pull Requests are preferred over very large submissions.

---

# Reporting Bugs

Bug reports should include:

- Operating system
- Jamovi version
- AssumptionsLab version
- Steps to reproduce
- Expected behavior
- Observed behavior
- Screenshots when appropriate

---

# Feature Requests

Feature requests should explain:

- The methodological motivation.
- The intended users.
- Expected benefits.
- Supporting references when applicable.

---

# Scientific Integrity

AssumptionsLab is intended for scientific research and education.

Contributors should ensure that all methodological recommendations are:

- Accurate
- Reproducible
- Transparent
- Properly referenced

---

# Code of Conduct

Please be respectful and constructive.

Scientific discussion is encouraged.

Personal attacks, discrimination, harassment, or abusive behavior will not be tolerated.

# Questions
